# token-eater-pet 배포

## 0. 왜 npm 이 아니라 GitHub Releases 인가

token-eater-pet 은 **Electron 데스크탑 앱**. 즉 사용자가 받는 건:

- macOS: `.dmg` 또는 `.zip`
- Windows: `.exe` (NSIS installer) 또는 portable
- Linux: `.AppImage` / `.deb`

이건 **바이너리 산출물**이라 npm 에 올릴 게 아님. npm 은 라이브러리/CLI 용. 데스크탑 앱은 GitHub Releases (또는 자체 호스팅) 에 바이너리 올리고, 사용자가 다운로드해서 설치.

**예외**: 만약 core 로직(예: `core/tokenSource/*`) 을 다른 프로젝트가 import 할 수 있게 라이브러리로 빼고 싶다면 — 그건 별도 npm 패키지 분리 작업이고, 이 skill 범위가 아님.

## 1. 사전 준비

체크리스트 — 빠진 것 사용자에게 물어보거나 안내:

- [ ] `git remote -v` 에 GitHub origin 잡혀 있는가? 없으면 `gh repo create` 또는 수동 생성 후 `git remote add origin`.
- [ ] `gh` CLI 설치 + 로그인 (`gh auth status`) — electron-builder 가 GH_TOKEN 으로 업로드 가능하지만 `gh` 가 가장 쉬움.
- [ ] (선택) Apple Developer 계정 — 코드 사이닝/notarization 하려면. 없으면 미서명으로 진행 (사용자가 Gatekeeper 우회 필요).
- [ ] `package.json` 의 `name`, `version`, `author`, `description` 이 그럴듯한가? 기본 description 빈 문자열로 돼 있을 수 있음.

## 2. electron-builder 도입 (최초 1회)

설치:

```bash
npm install --save-dev electron-builder
```

`package.json` 에 `build` 섹션 + scripts 추가:

```json
{
  "scripts": {
    "build": "vite build",
    "dist": "npm run build && electron-builder",
    "release": "npm run build && electron-builder --publish always"
  },
  "build": {
    "appId": "dev.iksung.token-eater-pet",
    "productName": "Token Eater Pet",
    "files": [
      "dist-electron/**/*",
      "dist/**/*",
      "scripts/statusline-shim.cjs",
      "package.json"
    ],
    "asarUnpack": [
      "scripts/statusline-shim.cjs",
      "node_modules/better-sqlite3/**/*"
    ],
    "mac": {
      "category": "public.app-category.developer-tools",
      "target": ["dmg", "zip"],
      "hardenedRuntime": false,
      "gatekeeperAssess": false
    },
    "publish": {
      "provider": "github",
      "owner": "<github-username>",
      "repo": "token-eater-pet"
    }
  }
}
```

**주의 사항**:

- `asarUnpack` 에 `statusline-shim.cjs` 와 `better-sqlite3` 필수. asar 안에 들어가면 Node 가 require 못 함 / shim 경로가 비정상.
- `appId` 는 reverse-DNS. 한 번 결정하면 바꾸지 말 것 (macOS 가 이걸로 앱 식별).
- `hardenedRuntime: false` + `gatekeeperAssess: false` = 서명 안 함 모드. 정식 배포 시엔 true 로 바꾸고 Apple Developer 계정 필요.

`appId`, `owner`, `repo` 는 사용자에게 확인하고 채울 것 — **단언하지 말고 물어볼 것**.

## 3. 버전 bump

```bash
npm version patch   # 0.0.1 → 0.0.2
npm version minor   # 0.1.0 → 0.2.0
npm version major   # 1.x → 2.0.0
```

이 명령이 자동으로:
1. `package.json` 의 version 업데이트
2. `git commit -m "0.0.2"` 생성
3. `git tag v0.0.2` 생성

push 도 같이:
```bash
git push origin master --follow-tags
```

## 4. 빌드

```bash
npm test                                            # 사전 검증
npm run postinstall                                 # Electron ABI 확실히
npm run dist                                        # dist/ + release/ 산출물
```

`release/` (또는 `dist/`) 에 `.dmg`, `.zip`, `latest-mac.yml` 같은 파일들 나옴.

**확인 후 사용자에게 보고할 것**:
- 산출물 위치
- 파일 크기 (sanity check — 0KB 면 빌드 실패)
- `.dmg` 더블클릭으로 마운트 + 앱 실행 한 번 — 사이닝 안 했으면 macOS 가 "확인되지 않은 개발자" 차단함. 우클릭 → 열기 로 우회.

## 5. 릴리스 업로드

### 옵션 A: electron-builder --publish

```bash
GH_TOKEN=$(gh auth token) npm run release
```

자동으로 GitHub 에 release 생성하고 산출물 첨부.

### 옵션 B: gh release create 수동

```bash
gh release create v0.0.2 \
  release/Token\ Eater\ Pet-0.0.2.dmg \
  release/Token\ Eater\ Pet-0.0.2-mac.zip \
  --title "v0.0.2" \
  --notes-file CHANGELOG.md
```

A 가 권장 (electron-builder 가 메타데이터 .yml 까지 같이 올림).

## 6. 릴리스 노트

`CHANGELOG.md` 가 있으면 거기서 추출, 없으면 직전 태그부터 커밋 메시지 모아서 작성:

```bash
git log --oneline $(git describe --tags --abbrev=0 HEAD^)..HEAD
```

**커밋에 AI 관여 흔적 절대 X** (사용자 글로벌 규칙). Co-Authored-By, Generated by 등 들어가지 않도록.

## 7. README 에 다운로드 안내 추가

릴리스 후 사용자가 받아가야 하니 README 에 다음을 박을 것:

```md
## 다운로드

[GitHub Releases](https://github.com/<owner>/token-eater-pet/releases/latest) 에서 OS 에 맞는 빌드 받기:

- macOS: `Token Eater Pet-<버전>-mac.dmg`
- (Windows/Linux 빌드는 TODO)

### macOS — 서명 없는 빌드 우회

현재 코드 사이닝 안 돼 있어서 처음 실행 시 macOS 가 막음:

1. 다운받은 `.app` 우클릭 → **열기** (더블클릭이 아니라)
2. "확인할 수 없는 개발자" 경고 → **열기** 클릭

한 번 우회하면 다음부턴 더블클릭으로 OK.
```

## 9. TODO / Future

이 skill 이 지금 안 다루는 것:

- **코드 사이닝 (macOS notarization)** — Apple Developer 계정 ($99/year) 필요. electron-builder 가 `CSC_LINK` / `CSC_KEY_PASSWORD` / `APPLE_ID` / `APPLE_APP_SPECIFIC_PASSWORD` 환경변수로 자동화. 받으면 그때 이 skill 에 추가.
- **자동 업데이트** — electron-updater 통합. 사용자 앱이 새 릴리스 폴링해서 자동 다운로드/설치. 코드 사이닝 사실상 필수.
- **Windows / Linux 빌드** — electron-builder 가 multi-platform 지원하지만 OS 별로 빌드 머신 필요 (또는 GitHub Actions matrix).
- **arm64 / x64 universal binary (macOS)** — `mac.target` 에 `{ target: "dmg", arch: ["arm64", "x64"] }` 또는 `"universal"`.
- **GitHub Actions CI** — 태그 push 시 자동 빌드/릴리스. `electron-builder --publish always` 를 워크플로우에서 실행.
